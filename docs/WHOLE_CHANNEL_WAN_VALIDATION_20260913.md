# 整频道模式：实际远程节点验证

2026-09-13 UTC，在已运行的增量节点 01 上使用独立测试容器完成。正式 Worker 没有替换或暂停，生产中心、数据库结构、每日 Clock、迁移批次和派发开关未修改。

## 实际执行的范围

中心使用临时 PostgreSQL、Redis 和 NATS JetStream；节点真正运行 Node 20.20.2、原 Go Rota 转发器、指纹网关和当前源码的共享 YouTubeJS 采集流程。NATS 使用 WSS，通过跨服务器 SSH 私有转发连接临时中心，不使用正式 NATS 账号或修改正式 nginx。转发只绑定回环地址。

中心使用原 `createCenterIncrementalProcessor` 和真正的 BullMQ Worker，消费隔离 Redis 中的独立队列前缀。原 Rota 管理服务为测试申请单独槽位，签发实际节点路由，真实代理直达 YouTube。生产 Rota 管理/路由读取凭据保留在中心；节点只得到临时中心令牌、路由公钥和临时 CA。

执行的 Plan 为 About＋Video：3 条首次发现视频＋1 条存量复采，使用上一轮真实数据确定相同锚点。两条路径使用同一 Rota 网络身份，成功对照的出口为 MX。中心按原业务和执行栅栏创建记录、入库及确认 BullMQ 任务完成。未启动 Feature 消费者、Agent 或搜索发布，不能把这次验证描述为整套每日 Clock 到页面/搜索发布的端到端验收。

这次入口直接创建一个受控测试执行器，中央接单就绪条件由专用测试保证；未经过 Dashboard 的安装/启停按钮或正式 supervisor 的自动接单配置。真实 Worker 启动/激活与混合版本保护已有上一阶段集成测试，本轮没有把它们替换成正式流量试验。

## 结果

第一次实际采集中，旧路径遇到 `FINGERPRINT_PROXY_TRANSPORT`，测试为固定比较条件设置了零次执行内换路，因此以路由预算耗尽结束该样本。随后整频道路径成功。该失败发生在临时 Plan，证据保留，**没有拿失败耗时计算提速**。

后续同出口的新旧对照通过：2 个子测试，含父测试共 3 个。该轮临时检查点位于内存文件系统，旧路径总耗时 16.94 秒，整频道 20.57 秒；整频道的 About 调用由约 6.26 秒增至 10.79 秒。虽然相邻详情等待由约 597 ms 降至 27 ms，但总耗时反而增加，不能隐藏此结果。

最后将检查点换为真实节点磁盘绑定目录，再次对照通过（2 个子测试，含父测试共 3 个）：

| 指标 | 原逐指令路径 | 整频道路径 |
| --- | ---: | ---: |
| 入队至中心 BullMQ 完成，含冷启动 | 13.759 s | 13.179 s |
| 节点进程计时，含会话准备和收尾 | 11.303 s | 10.286 s |
| About 调用 | 1.832 s | 2.201 s |
| 上传列表调用 | 0.952 s | 0.999 s |
| 四条详情调用合计 | 5.107 s | 4.617 s |
| 三处相邻详情之间等待合计 | 0.732 s | 0.104 s |
| 采集指令数 | 6 | 1 |
| 采集结果上传次数 | 6 | 1 |
| 实际 YouTube HTTP 请求 | 15 | 15 |
| YouTube HTTP 失败 | 0 | 0 |
| 成功结束的原始执行 Attempt | 1 | 1 |
| 完成后的待回传文件 | 0 | 0 |
| 退役回执中的在途连接 | 0 | 0 |

整频道输入读取约 22 ms、结果上传约 89 ms。上传 ACK 后仍有中心入库和会话清理；不能把它当作节点全部占用时间。上表中各时间的计时范围不同，部分通信与采集重叠，不能机械相加。

最终磁盘轮中，播放量、点赞数、评论数、新旧视频 ID、类型、描述、日期和时长一致；评论首屏返回数与数组长度相符，评论 ID 集合、作者与正文一致，允许相对发布时间换算和排序位置变化。两条路径均 About complete、Video complete、channel run done；网络绑定 retired，回执 `in_flight=0`，节点退出码为 0，磁盘结果目录无残留文件。

可以确认实际跨服务器的整频道采集、回传、原栅栏入库和正常收尾成立，并减少了逐视频通信等待。不能从一个小频道、低并发、冷启动且通过 SSH 转发的样本推算 40 个正式 Worker 的总体提速；频道信息调用波动足以覆盖控制开销节省。
