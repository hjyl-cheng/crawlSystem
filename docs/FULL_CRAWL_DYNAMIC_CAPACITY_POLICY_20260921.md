# 全量远程 Worker 动态容量策略

全量远程 Worker 与增量 Worker 使用同一套容量原则，不再按中心配置设置固定的远程槽位上限。

全量节点不再使用白名单。中心监督器读取已登记的 active 节点及其部署，支持多个全量远程服务器；节点凭据、部署归属和任务隔离校验继续生效。旧的 `REMOTE_NODE_FULL_CRAWL_NODE_IDS` 不再读取。

## 容量来源

- `REMOTE_NODE_LOCAL_CHANNEL_SLOTS` 提供中心本地固定 channel 预算。
- 所有处于 active 状态的远程部署登记数量计入同一个 channel 预算。
- 中心通过 Rota capacity 接口自动补足所需容量；总 channel 预算不得超过 500。
- 每个节点的 CPU、内存、磁盘和 spool 余量由节点监控及容器验证决定。

全量中心仍保留一个本地兼容执行槽，用于原有全量处理器和收尾流程；该兼容槽不构成远程 Worker 的数量上限。

## 扩容和接单

部署流程先登记并申请容量，再执行节点容器部署和连接检查。接单容量始终等于该节点当前已部署且未退役的 Worker 数量；管理员只能开启或暂停接单，不能单独设置 `configuredCount` 或 `allowedCount`。节点已开启接单时，扩容完成登记的新 Worker 自动加入目标集合，并在心跳和执行监督器就绪后接收任务。

`configuredCount` 仅作为兼容状态字段，返回当前已部署 Worker 数量；`allowedCount` 表示开启接单后实际被选中的 Worker 数量，暂停时为 0。暂停只停止新任务，正在执行的全量阶段继续收尾。

## 缩容和恢复

缩容先撤销目标槽位的接单请求，等待全量任务、阶段结果、网络绑定和恢复证据全部结清，再删除容器并保留退役记录。Worker 断连或中心重启时，任务保持受保护状态，恢复流程确认安全后才重新接纳。

`REMOTE_NODE_FULL_CRAWL_TOTAL_SLOTS` 不再参与全量容量计算；旧配置可以保留在历史 Compose 文件中，但新中心不读取该变量。

## 单 Worker 维护暂停

`REMOTE_NODE_FULL_CRAWL_PAUSED_WORKERS` 保存逗号分隔的 `节点 UUID/槽位名`，例如 `8a07de4f-a3ee-428f-a959-2aee9c7b6be7/full-crawl-1`。暂停只影响指定节点上的该槽位。中心不会为暂停槽位接新任务；节点重新开启接单、扩容或中心重启均不会解除暂停。已有执行的恢复证据继续保留。

部署登记返回 `pausedSlots`；管理面板及节点安装器将这些服务设为 `restart: 'no'` 和 `profiles: ['paused']`，停止已有容器，跳过启动及在线连接要求。暂停槽位仍属于已部署数量，但不占用允许接单数量。解除暂停需要明确删除暂停配置并恢复该槽位部署，不应通过删除数据库记录或暂存目录实现。
