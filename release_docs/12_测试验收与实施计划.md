# 12 测试验收、团队决策与分阶段实施计划

状态：团队评审与任务拆分稿，不是已批准的生产变更单。基线见 [01](01_目标范围与系统基线.md)。本轮交付仅为这 12 份文档及其检查，没有运行新的功能/负载测试或实施部署。

## 团队评审议程

1. 核对当前事实：源码提交、角色版本、45 个远程登记、40 个 Full Crawl 容器、两库容量和根盘余量。
2. 确认业务目标：新增频道量、每日增量覆盖、完成时限、历史保留、恢复要求。
3. 确认正确性边界：Plan/Run/代次、网络身份、回执与发布语义。
4. 对已有性能证据排序，确定近期只读测量与容量处理任务。
5. 决定先拆哪些物理角色、是否做结果解耦；OLAP/分片是否进入近期范围。
6. 分配负责人、依赖、验收标准和回退条件。

## 分阶段交付

### 阶段 P0：建立事实与控制容量风险

输入：第 01 份的现场快照与当前发布版本。

交付：数据卷/目录容量清单、数据库增长采样、有效接单/执行口径、中心时延分解方案、现网镜像配置矩阵、备份恢复状态。对测试命名实例按责任人逐项确认归属与保留要求，不在盘点时自动删除。

验收：所有核心数据都有存储位置和责任人；明确剩余空间能覆盖多久及扩容/恢复需求；性能问题分成已证实与待测量两类。

### 阶段 P1：低风险性能与稳定性修复

候选内容：高频慢 SQL、锁持有时间、连接预算、统计缓存/汇总、错误收尾与重试风暴、合理的 Worker/后处理并发。

交付：可重复基线、针对实际故障的测试、改动后的同口径结果、监控与回滚步骤。每项只在证据支持时实施，不因为旧文档曾有某个故障就重复修改。

验收：正确性不退化，有效完成量或目标时延改善，最老积压不持续增长。若无收益，撤回该优化而不是继续增加组件。

### 阶段 P2：物理资源隔离

依赖：D02/D03 与恢复演练完成。

交付：采集库/重计算/业务数据等选定角色的目标主机清单、私网与权限、配置组合、数据迁移方案、灰度和回退规格。

验收：迁移前后数据与发布口径一致，旧写入端隔离，核心资源余量改善，自发现和增量均跑通。此阶段不自动包含数据库分片或中心多活。

### 阶段 P3：结果应用解耦〔条件性〕

依赖：D05 通过，证明等待中心应用明显限制采集槽位周转。

交付：状态机/schema、原子待应用记录、独立消费者、槽位与业务归属分离、有限积压、故障恢复、协议兼容与回滚。

验收：各提交边界强杀后不漏应用、不重复副作用；同频道后续任务不越过未应用结果；数据库跟不上时自动抑制新接单。不能以“上传 ACK 更快”作为完整验收。

### 阶段 P4：分析负载隔离〔条件性〕

依赖：D07 通过，存在汇总/缓存不能充分解决的分析负载。

交付：独立分析节点、第一批分析模型、可靠同步与回填、口径校验、统计 API 切换与降级。

验收：源统计开销下降；重传/迟到/删除/更正正确；分析服务中断后可恢复；源日志和同步积压不无限增长。不能以查询单次更快就忽略同步对采集的成本。

### 阶段 P5：长期水平扩容〔条件性〕

依赖：D06/D08 与单库/单中心容量证据。

交付：多中心职责归属、频道分片目录与路由版本、分片内事务与调度、全局去重、在线迁移、热点处理、业务发布与备份恢复方案。

验收：新增节点带来可测持续容量提升，旧路由拒写，迁移无丢失/乱序，单分片故障隔离与恢复可演练。对比应用层分片和原生分布式数据库后决定实现，不预设必须自研。

## 测试矩阵

| 维度 | 必测场景 | 成功标准 |
| --- | --- | --- |
| 自发现 | 评分、分页续跑、重复频道、已有频道、准入筛选 | 原候选规则与派发代次正确 |
| Full Crawl | 新旧冻结契约、列表 partial、详情/评论、修复、迁移输入 | 完整性与资格规则保持，恢复不乱写 |
| 增量 | About/Video/组合/Agent-only、首次发现与复采、休眠 | 原 Plan、检查点、字段状态与 Clock 正确 |
| API | 等待、迟到结果、重启、继续下一个频道 | 原配额与 continuation 正确，槽位行为可解释 |
| 远程传输 | 分块、缺块、损坏、重复、丢 ACK、重连 | 完整性校验、合法幂等、不丢未确认结果 |
| 归属 | 同 slot 多实例、旧代次、中心竞争、锁组断开 | 失去归属不能写，合法实例能恢复 |
| 进程故障 | 节点与中心在提交点前后 SIGKILL | 符合第 04 份矩阵，重复请求范围明确 |
| 发布 | 重复版本、乱序、撤回、缺口、Projector 重启 | 业务版本合法、内容与投影一致 |
| 数据增长 | 大频道、高历史量、索引/清理/备份竞争 | 内存与事务有界、无无限积压 |
| 性能 | 分链路与混合流量、慢代理、SQL 变慢 | 有效完成量、尾延迟和稳定性同时达标 |
| 部署 | 旧库升级、新库安装、混合版本、回滚 | 不破坏在途任务、配置与身份兼容 |
| 灾备 | 单库、跨库不同恢复点、对象/队列/节点证据 | 核验 RPO/RTO 与数据差异，不只看启动 |
| OLAP〔若实施〕 | 重放、迟提交、更正、删除、断点、重建 | 与源口径对账、延迟可控、同步有界 |

## 结果记录格式

每份测试/性能报告至少包含：源码提交、镜像摘要、环境拓扑、schema/配置版本、数据规模与分布、代理条件、起止时间、执行/通过/失败/跳过数量、指标计算口径、原始证据位置、异常和限制。

性能报告同时提供吞吐、尾延迟、错误/重试、积压、CPU/内存/I/O 与数据库开销。跨模式测试随机或交替顺序并保持任务可比；外部网络波动不能误算成代码收益。

通过标准要在试验前确认。没有压测数据时，目标数值写“待基线确认”，不能把设计建议写成已达到指标。

## 发布准入与阶段关闭

1. 关键正确性和故障测试通过；skip 有明确原因，不伪装成执行成功。
2. 兼容性、新旧版本和回滚验证完成。
3. 资源、磁盘与备份恢复预算满足目标窗口。
4. 监控和告警能够发现新增失败模式。
5. 灰度真实链路完成，观察完整目标周期后再扩量。
6. 文档、角色版本清单、决策和剩余风险同步更新。
