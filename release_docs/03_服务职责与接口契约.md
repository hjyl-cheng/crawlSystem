# 03 服务职责、依赖与接口契约

状态：当前源码契约索引，后续接口变更必须补兼容说明。基线见 [01](01_目标范围与系统基线.md)。本文件用于开发分工、网络访问设计和部署拆分。

## 服务与数据权限

| 角色 | 当前入口或 Compose 服务 | 输入/输出 | 基础依赖 |
| --- | --- | --- | --- |
| 管理 API | `qybullmq-api`、Dashboard/Auth | 管理请求、状态查询 | 按角色访问数据库/Redis，Dashboard 使用受限业务审计通道 |
| Controller | `src/controller.js` | 派发、背压、恢复与批处理 | 采集库、Redis、Rota 控制 |
| Query Quality | `worker-query-quality` | 词质量任务、评分结果 | 采集库、Redis、Rota |
| Discover | `worker-discover` | 分页任务、候选与全量任务 | 采集库、Redis、Rota |
| Full Crawl | `worker-channel` | 首次全量与详情修复 | 采集库、Redis、MinIO、Rota |
| 本地增量 | `worker-incremental` | 增量 Plan、观测 | 采集库、Redis、Rota，按配置使用 NATS 接单通知 |
| 远程增量节点 | `runRemoteNodeIncremental.mjs` | 采集指令、本地检查点、结果 | 节点凭据、NATS/WSS、本地 relay、代理出口；不配置中心数据库凭据 |
| 远程中心 | `runRemoteNodeCenter.mjs` | 原增量任务、节点接入、结果应用 | 采集库、直连会话、PgBouncer、Redis、NATS、Rota |
| 补采/API | `worker-content-enrich`、`worker-data-api` | 补采、API 请求及续跑证据 | 采集库、Redis，按角色访问网络与密钥 |
| Agent/Finalize | `worker-agent`、`worker-finalize` | 后处理、最终化材料 | 采集库、Redis；Agent 模型/Python，Finalize 对象存储 |
| Feature | `feature-ingest`、`feature-scheduler-daily`、`feature-dispatch` | 观测、Clock、Plan 与派发 | Feature schema、认证接入、Redis 等角色依赖 |
| 发布与业务投影 | Publisher、Ingress、Reconciler、Projector | Revision、Outbox、业务投影 | 采集/业务侧分权访问 |
| Rota | `rota-core` 与独立数据库 | Slot、Lease、Route 管理 | 代理库存与网络身份状态 |

详细可执行入口见 [角色表](../docs/QYBULLMQ_ROLES.md) 和 [Compose](../deploy/compose.yml)。同一 QYBullMQ 镜像可承担多个角色，`WORKER_QUEUES` 决定职责；不要复制一套新 Full Crawl 业务实现。

## 队列清单与契约

以下名称来自 [queues.js](../services/qybullmq/src/queues.js)：

| 队列 | 业务粒度 | 消费者 |
| --- | --- | --- |
| `youtube-query-quality` | 查询词质量任务 | Query Quality |
| `youtube-discover-page` | 某查询的一页及 continuation | Discover |
| `youtube-channel-crawl` | 频道首次全量及指定修复 | Full Crawl |
| `youtube-channel-incremental` | 原频道 Plan | 本地增量或远程中心协调器 |
| `youtube-content-detail` | 详情补采 | Channel/详情 Worker |
| `youtube-content-enrich` | 内容增强 | Content Enrich |
| `youtube-data-api-batch` | 共享 API 批处理 | Data API |
| `youtube-agent-batch` / `youtube-agent-incremental` | 全量/增量 Agent | Agent Worker |
| `youtube-finalize` | 最终化任务 | Finalize Worker |

队列 job ID 不足以单独授权数据库写入；还要验证 Run、Plan、dispatch generation 和业务所有权。队列 prefix 是环境隔离的一部分，测试不允许混用生产 prefix。

默认 BullMQ 重试与保留值只是默认配置，具体任务可覆盖；不能用队列 TTL 代替数据库保留策略，也不能把队列清空作为故障恢复。

## 远程接口与消息

当前网关保留 HTTPS 协议，NATS 路径复用原业务语义。下表为接口族，不是允许任意客户端自行构造生产请求的说明。

| 接口/消息族 | 关键数据与检查 |
| --- | --- |
| 领取 `claim` | 节点、slot、持久 claim 身份；同一领取重放不创建另一个任务 |
| 节点/任务心跳 | 精确实例、代次、连接期限；旧代次不能靠续租复活 |
| `commands` / `whole_channel_input` | 原任务 ID、generation、版本及冻结输入 |
| `network_grant/release/abandon` | 原网络绑定、签名路由、合法执行归属 |
| `channel_result/whole_channel_result` | 节点身份、任务代次、内容 hash、大小、结果类型 |
| `receipt/result_receipt` | 区分传输回执和业务状态，不等于发布完成 |
| 内部部署 prepare/status | 管理员凭据；不属于节点普通权限 |

NATS 源码中的结果 subject 为 `qy.remote.results.*`，RPC 订阅为 `qy.remote.rpc.*.*`。节点具有受限 subject 权限。LISTEN/NOTIFY 或 NATS 通知负责唤醒；真正任务状态仍来自已提交 SQL，通知不是所有权证明。

整频道协议当前版本为 1，二进制分块 512 KiB、逻辑载荷上限 32 MiB，逐块及整体校验大小/hash。Base64 与 JSON 封装会增加传输大小，网络预算不能只按二进制载荷计算。修改上限需要同步修改双方校验、内存预算和恢复测试。

代码来源：[NATS 中心](../services/qybullmq/src/remoteNodes/natsCenter.js)、[协议](../services/qybullmq/src/remoteNodes/wholeChannelProtocol.js)、[网关](../services/qybullmq/src/remoteNodes/gateway.js)。

## 数据库连接语义

普通事务走配置的 PgBouncer/事务连接池；远程中心的 session advisory lock 和 LISTEN 必须使用保留会话语义的直连。不能把所有 DSN 统一替换为事务池地址。

当前中心入口源码池配置：gateway 12、心跳 4、结果 8；执行锁由 `SupervisionGuards` 默认 4 组专用会话承载。它们不是数据库的全局连接预算，其他 Worker、Feature、发布、Dashboard 和运维仍占连接。

每次事务需设置必要的上下文；不能依赖事务池复用后的旧 session 状态。详细依据见 [连接共享记录](../docs/POSTGRES_CONNECTION_SHARING_20260912.md)。

## 发布边界

Publisher 无业务库直写职责；Ingress 不应该获取采集数据库权限。保留已有 Revision/Outbox、hash、顺序和版本检查。业务 API 读当前投影，不能绕过发布边界直接把采集临时结果当成正式业务数据。

OLAP 业务数据同步应从已发布业务数据或受控发布事件出发；爬虫运营事件走单独数据集，避免两个口径混用。

## 协议与版本升级要求

1. 记录受影响生产者、消费者、表结构、镜像和最低兼容版本。
2. 明确新旧载荷是否都能读取；失败时拒绝未知版本而非静默丢字段。
3. 先部署兼容 schema/中心，再排空并升级选定节点，核对实例运行版本。
4. 验证旧载荷重放、重复回执、API waiting、新旧节点共存和回滚。
5. 密钥放运行目录或 secret 文件，不进入文档、镜像、Git 或日志。节点不获得数据库/Redis/MinIO 的中心凭据。

待评审扩展：Full Crawl 远程接入、接收与应用分离、多中心分配、OLAP 消费出口。每项新增契约需说明失败语义和兼容策略，不能只增加一个消息 subject。
