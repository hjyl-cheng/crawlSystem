# 04 数据一致性、执行归属与恢复设计

状态：现有约束说明与待开发方案边界。基线见 [01](01_目标范围与系统基线.md)。负责人角色：核心后端、Rota、数据库、测试。

## 不可破坏的保证

系统使用至少一次执行/传输与受栅栏保护的幂等持久化，不承诺外部 YouTube 请求只发生一次。优化并发不能删除锁、业务代次或身份检查来换取表面吞吐。

| 对象 | 需要保护的内容 |
| --- | --- |
| Discover 候选 | 同频道去重、来源证据、snapshot 派发代次 |
| Full Crawl Run | 冻结抓取契约、检查点、资格判定、原业务执行归属 |
| 增量 Plan | 冻结任务域、预算、视频周期、策略版本与执行代次 |
| 远程 Task | node/slot/instance、generation、租约与协调者所有权 |
| Rota Route | Slot/Lease/Route generation，在途请求期间不跨身份切换 |
| 视频写入 | checkpoint、内容处置与字段证据，不让陈旧执行覆盖新状态 |
| 发布 | Revision、hash、顺序、撤回和业务版本关系 |

Rota 领域词汇以 [CONTEXT.md](../CONTEXT.md) 为准。Execution-Locked Slot 和 Lease-Owned Idle Slot 的路由变更规则不同；历史代理健康信息不能替代正在执行任务的网络证据。

## 接收、应用与发布是不同提交点

```text
外部采集完成
    |
节点本地 journal/spool 持久化
    |
JetStream 接收消息
    |
中心验证并持久保存完整回执/结果
    |
原业务事务应用内容、检查点和观测
    |
任务/会话收尾
    |
后处理、发布和业务投影完成
```

JetStream ACK 不能直接替代中心业务回执；中心回执也不能替代应用完成或发布完成。完整与不完整分块、合法等待与失败必须分别处理。

正常整频道路径当前仍在中心应用完成和会话关闭前占用节点槽位。API waiting 依照原 continuation 释放容量，不能将这一特例推广成所有结果已经异步应用。

## 恢复矩阵

| 故障边界 | 已有证据/恢复依据 | 验收要求 |
| --- | --- | --- |
| 网络请求完成但检查点未落盘 | 原任务及已落盘检查点 | 可能重复请求；不能伪造已采完 |
| 本地结果已落盘，上传中断 | spool/journal | 重传原结果，未获合法回执不得丢弃 |
| 中心已接收，节点未收到回执 | 精确回执身份与 hash | 重传幂等，不重复应用业务副作用 |
| 只收到部分结果分块 | 分块 manifest/顺序/hash | 不把不完整数据当作完整结果 |
| 中心接收后、应用前退出 | 已接收证据、原 Plan 与新执行栅栏 | 兼容范围内复用证据，新所有者重新校验 |
| 应用事务失败 | PostgreSQL 事务与检查点 | 失败事务不留下半完成的本域写入 |
| 原执行代次失效 | generation/业务所有权 | 拒绝陈旧写入，保留必要诊断证据 |
| 锁组连接断开 | 分组会话与监督器恢复 | 相关 slot 立即失去写入授权，其他组独立 |
| API 结果延迟 | 中心 API 请求和 continuation | 不重复占用采集槽；恢复到原执行预算 |
| 发布中断 | Outbox/Inbox/Revision | 按原幂等、顺序与 hash 续传，不标假成功 |

已有进程强杀测试能证明特定边界的进程恢复，不能证明节点磁盘损坏、掉电、跨机房故障和备份恢复均无损。灾难恢复另见 [11](11_备份与灾难恢复手册.md)。

## 暂停、排空与恢复接单

暂停接单只阻止新任务，不能立即删容器、清空 spool 或回收活动身份。排空需同时确认：接单已关闭、活动业务执行完成或进入原机制允许的交接、网络会话已收尾、节点待回传文件已确认处理。

仅凭队列 active=0、节点在线或 Docker healthy 的单一信号不能决定排空完成。恢复接单需要重新核对部署/镜像、实例身份、路由就绪和中心消费者资格。

## 待评审：接收与应用解耦

若性能测量证明“持久接收后等待应用”占比高，可以设计独立结果应用队列，但必须一次覆盖以下内容：

1. 持久接收结果与建立待应用工作之间具有原子关系，或有可证明不遗漏的 outbox/reconciler。
2. 把“采集槽位可释放”和“频道业务执行已完成”分开；同频道后续任务不能越过未应用结果。
3. 任务租约失效后，待应用记录拥有怎样的合法写入授权，需要显式设计，不能复用过期网络租约。
4. 多消费者领取使用独占归属、幂等键和版本检查；重复投递不重复观测、不重复发布。
5. 网络会话安全关闭后才能释放相应 Rota 资源。
6. 待应用数量、字节数和最老年龄均有上限；超限减少新采集，不丢弃已持久接收结果。
7. 任一提交点崩溃都能从持久状态恢复；回滚旧程序前处理新状态的兼容性。

候选状态名可用 `received_pending_apply/applying/applied` 讨论，但这些不是当前已存在的新 schema，不能直接写入生产。

## 待评审：多中心与数据分片

当前存在按 slot 的监督锁和竞争中心相关测试，不等于全部中心职责已经支持生产多活。还要验证全局配置写入、凭据同步、通知消费、结果领取、清理、协调者回收和发布管理等职责。

分片时让频道及其 Run、Plan、内容与观测尽量共址。迁移频道归属需要冻结新接单、收尾旧执行、同步增量、核对数据、原子切换路由版本并拒绝旧路由写入。不能用修改一个数据库 URL 完成分片切换。
