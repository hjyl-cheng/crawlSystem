# 08 开发环境、代码导航与本地联调

状态：依据当前仓库整理的开发指南。基线见 [01](01_目标范围与系统基线.md)。本文命令供开发团队后续在独立开发环境执行，本轮没有安装依赖、创建环境或运行采集。

## 源码与职责

| 目录 | 职责 | 常用入口 |
| --- | --- | --- |
| `services/qybullmq` | 调度、采集、Agent 调用、最终化、发布 | `src/worker.js`、`src/controller.js`、`src/queues.js` |
| `services/qybullmq/src/remoteNodes` | 远程身份、运输、协调、检查点与整频道执行 | `incrementalCoordinator.js`、`wholeChannelStore.js`、`natsCenter.js` |
| `services/remote-node` | 远程连接、采集与中心镜像 | `Dockerfile`、`Dockerfile.collect`、`Dockerfile.center` |
| `services/local-agent` | Python 画像推理和模型 | Python 包、模型包与测试 |
| `services/feature-engine` | 观测接入与 Clock | `src/feature_engine`、`sql/schema.sql` |
| `services/feature-dispatch` | 增量派发 | package scripts 与源代码 |
| `services/rota` | 网络身份与代理管理 | `core/internal`、Go 测试 |
| `services/dashboard` / `services/auth` | 管理页面与认证 | `src/server.js`、节点部署模块 |
| `database` | 新库结构快照和参考 schema | `bootstrap`、`init` |
| `deploy` / `scripts` | Compose、构建、验证与运行入口 | `compose.sh`、`build-images.sh` |

源代码是唯一开发位置；运行容器、历史 overlay、临时导出目录不是另一个源码根。当前线上角色镜像并不完全相同，复现生产问题时先确定受影响角色的真实版本。

## 开发环境前置条件

- Git、Git LFS、Docker Engine 和支持仓库 Compose 语法的 Compose v2。
- Bash、OpenSSL、Python 3 与 venv；Node/npm 版本需与相关镜像及依赖锁文件兼容。远程采集镜像当前使用 Node 20，不能拿另一主版本的通过结果替代生产镜像验证。
- Rota Go 版本以 `services/rota/core/go.mod` 和构建文件为准；总测试入口无本机 Go 时使用配置的 Go 容器。
- 足够的隔离测试磁盘、内存与端口。当前中心根文件系统余量低，不建议把它作为不受限的开发压测主机。

在新开发 checkout 中执行：

```bash
git lfs install
git lfs pull
./scripts/setup-dev.sh
./scripts/verify.sh
```

`setup-dev.sh` 会安装四个 Node 服务依赖并建立根目录 `.venv`，安装采集 Python 依赖、Local Agent 和 Feature Engine。它会写入开发环境，不能当成生产只读检查命令。

模型文件要验证真实 LFS 内容，不能将指针文本打包进镜像。代码/模型变更与运行凭据分离，凭据只存在未提交的环境目录。

## 隔离运行

以下是环境生成与静态检查，不自动证明端到端可采集：

```bash
./scripts/bootstrap.sh smoke
./scripts/compose.sh smoke config --quiet
./scripts/compose.sh smoke config --services
```

`bootstrap.sh` 生成运行配置和凭据。要确认 `QY_DEPLOYMENT_MODE`、数据库、Redis prefix、对象存储 bucket、发布 stream 与 Rota 资源均属于测试范围，再按 [09](09_部署升级与回滚手册.md) 启动指定角色。

不要为了简单把所有测试 DSN 指向生产库。部分集成用例会建表、清理或重置夹具；必须使用入口要求的独立库名与环境变量。

## 本地验证层级

### 仓库标准检查

```bash
./scripts/test.sh
./scripts/verify.sh
```

`test.sh` 覆盖 QYBullMQ、Dashboard、Auth、Feature Dispatch、Local Agent、Feature Engine 和 Rota。部分集成测试在缺少显式环境时会跳过，因此命令退出 0 不等于所有数据库/远程恢复测试都执行过。

### 按改动选择测试

在 `services/qybullmq` 中，现有入口包括：

```bash
npm run test:remote-nodes
npm run test:remote-fence
npm run test:remote-handoffs
npm run test:remote-center
npm run test:remote-deployment
```

这些命令不是相互替代关系。先阅读相应用例的数据库/Redis/NATS 需求并创建隔离服务；记录执行、失败与 skip 数量。真实节点/YouTube 测试使用专用入口，涉及网络与资源分配，不能混在无条件单元测试里。

Dashboard 示例：

```bash
npm --prefix services/dashboard test
```

完整测试矩阵见 [12](12_测试验收与实施计划.md)。不要对仅文档改动启动整套生产依赖；文档主要检查引用、命令入口和事实一致性。

## 必须跑通的联调场景

| 场景 | 需要观察的终点 |
| --- | --- |
| 查询词 → Discover → 新频道 Full Crawl | 候选和派发代次正确，原采集完整性规则成立 |
| Full Crawl → Agent/Finalize → 发布 | 数据进入目标业务版本，非仅 Worker 无异常 |
| 采集观测 → Feature → 增量 Plan | 原 Clock 域和预算被保留 |
| 整频道远程增量 | 节点持久结果、中心合法回执、数据应用、会话释放 |
| API waiting | 槽位释放与原 Plan 续跑，无重复业务副作用 |
| 节点/中心重启 | 旧代次拒写，合法证据恢复，重复消息幂等 |
| OLAP 试点〔将来〕 | 源口径一致、重复/迟到可处理、同步故障不丢数据 |

## 修改契约与数据库的方法

先定位 owning module 和对应 schema，列出生产者/消费者及影响表。优先添加兼容字段/版本，避免同一发布中删除旧程序仍在读取的结构。明确数据回填是否需要，与 schema 安装分开。

`database/bootstrap/*.sql` 用于新库初始化；运行迁移跟随所属服务。旧参考快照不能直接当作运行迁移重复执行。schema 变更需要测试新库、旧库升级和应用回滚，不只验证“空库能启动”。

发布版本、执行栅栏、字段状态或错误类型发生变化时，补充真实调用路径的契约测试。避免用浅层 mock 测试证明实际上跨事务/多实例的行为。

## 开发提交与交接

每项任务交付代码、必要 schema/配置、相应测试、版本兼容说明、监控变化及回退方式。PR 写清问题触发条件、最终行为和验证范围。性能 PR 提供可比基线；未量化的收益只写为假设。

构建生产发布镜像要求对应已提交源码，并遵守仓库不可变镜像规则。不要在活跃容器里替换 JS 文件，或把未经记录的 overlay 当成完整发布。
