## 一、先统一“错误码”的含义

当前没有一份覆盖所有链路的统一错误码注册表。必须分开保存下面六类信息，不能把日志里一个字符串直接当成最终处理指令。

| 类型 | 当前例子 | 应如何理解 |
| --- | --- | --- |
| 程序错误码 `error.code` | `PARSER_CONTRACT_ERROR`、`STALE_LEASE` | 程序／协议提供的身份；并非全部大写，部分异常根本没有 code |
| 异常类型 `error.name` | `IncrementalPlanContractError`、`IdempotencyConflict` | 不等于 code；跨进程需显式保留 |
| HTTP／协议状态 | 403、409、503 | 要带来源：YouTube、Data API、Agent、中心接收 API 的相同数字含义不同 |
| 分类器决策 `kind` | `proxy_transport`、`database_contract` | 由证据和调用路径计算，可进一步被系统错误策略覆盖 |
| 业务结果 `status/reason/reason_code` | `dormant`、`subscriber_count_below_minimum`、`upcoming_live` | 可能是正常完成、筛选淘汰或未来复查，不一定抛异常 |
| 数据库／运行时原生码 | SQLSTATE `23505`；DOMException 数字 20、23 | 不应混成 HTTP 码；必须保留 constraint、原始 name 与 native_code |

判定必须回答：**哪个阶段、哪个实体、哪种证据、谁仍有执行权、哪一步已经持久完成**。`terminal` 通常表示当前操作停止重试，并不表示永久删除频道。

## 二、日常处理速查

本表中的“建议”是面向重构的策略，不表示当前所有路径已经统一实现。

| 情况 | 当前可见标识 | 当前处理要点 | 建议与禁止事项 |
| --- | --- | --- | --- |
| 频道明确被终止／关闭 | `failure_kind=channel_removed`＋具体 `removed_reason` | 频道生命周期处理器要求明确文本证据；持久登记移除后停止当前频道任务 | 保存证据与来源；不能凭任意视频 404 移除频道 |
| 单个视频私密／不可用 | `access_status=private/unavailable` | 视频级排除或更新访问状态；可低频复查 | 不改变整个频道的存续结论 |
| 页面出现机器人挑战 | `youtube_challenge`；可能有 `reason_code=bot_challenge` | 当前路由策略记录挑战并冷却；受管路径可持久化检查点后交接 | 降速、遵守访问限制和重试预算；不能当成空数据成功 |
| 限流 | `youtube_rate_limited`、HTTP 429 等 | 冷却／路由重试策略 | 保留 Retry-After，限制总体速率；不要所有节点同时重试 |
| 网络／代理异常 | `proxy_transport` 或 `upstream_transient` | 根据来源证据决定路由动作 | 不按 timeout 一个单词断定代理坏了 |
| 解析契约变化 | `PARSER_CONTRACT_ERROR`／`IncrementalPlanContractError` | 通用策略停止当前重试 | 保存样本和解析版本，修复后受控重放；不要把字段缺失填成 0 |
| 空 uploads 且证据充分 | `uploads_empty`，必要时 `UPLOADS_COUNTRY_RECHECK` | 先复核空列表与地区，再进入休眠判定 | 不等于频道删除 |
| 空 uploads 但无法证明为空 | `UPLOADS_EMPTY_RESPONSE_UNVERIFIED` | 抛异常而非输出正常空列表 | 保留原始证据；禁止推进“已完整扫描” |
| API 结果尚未回来 | `VIDEO_API_PENDING` | 等待下游／延期 | 不计为采集失败，不再次启动整轮抓取 |
| 租约暂未就绪 | `RotaSlotDeferredError`＋reason | 延期；异常本身无 code | 等待资源，区别于执行身份冲突 |
| 旧执行已经失权 | `CANDIDATE_ATTEMPT_FENCE_STALE` 等 | 停止旧执行写入，不替新执行发布失败 | 不能在旧执行内换一个 ID 继续写 |
| 数据库契约错误 | SQLSTATE `23502/23503/23505/23514` 等 | 未被调用方处理的错误可能进入 `database_contract` | 查看具体约束和提交阶段；不能一律忽略或无限重试 |
| 数据库提交时断线 | 连接异常／无固定统一码 | 不能单凭异常判断事务是否已提交 | 按原操作键查询主库回执，必要时幂等重试 |
| 结果提交后未收到回执 | `NATS_RESULT_PENDING` 等 | 结果可能已经持久收到 | 重送同一结果身份，禁止立即重采或删本地结果 |

## 三、频道本身的业务结论

### 3.1 明确的频道移除证据

来源：[channelLifecycle.js](../services/qybullmq/src/channelLifecycle.js)，消费者：[worker.js](../services/qybullmq/src/worker.js)、[incrementalTerminalFailure.js](../services/qybullmq/src/incrementalTerminalFailure.js)。以下都是 `removed_reason`，不是 `error.code`。

| 证据匹配情况 | removed_reason | 统一记录 |
| --- | --- | --- |
| channel/account 被 removed/terminated，且明确 community guidelines | `community_guidelines` | `failure_kind=channel_removed`，`removed_source=youtube_alert` |
| channel/account 因 copyright infringement 被终止 | `copyright_termination` | 同上 |
| `this channel does not exist` | `channel_not_found` | 同上 |
| `this account has been closed` | `owner_closed` | 同上 |
| `this account has been terminated` | `account_terminated` | 同上 |

当前实现主要依赖英语正则，对错误及直接 cause 文本做有限提取；初始页还可从 ERROR alert 取证。未匹配不代表频道肯定存在；它只表示当前移除分类器没有拿到足够证据。

通用 YouTube 分类器的 `content_terminal` 范围更宽，包含视频、播放列表、私密内容和缺失页面。它不能替代这里的频道移除判定。日志事件 `terminal_channel_persistence_failed` 表示移除状态持久化失败，需要对账，不能仅凭任务停止就认为移除已成功登记。

### 3.2 自发现、订阅人数与资格筛选

来源：[channelQualification.js](../services/qybullmq/src/channelQualification.js)、[channelApiFallback.js](../services/qybullmq/src/channelApiFallback.js)、[discoveryPagePolicy.js](../services/qybullmq/src/discoveryPagePolicy.js)。

| 场景 | 当前状态／原因 | 应如何解读 |
| --- | --- | --- |
| 自发现阶段没拿到订阅人数 | `qualified=true, status=needs_snapshot` | 留给频道快照继续验证，不能直接判不合格 |
| 要求订阅人数验证，但值缺失／无效 | `subscriber_count_unknown` | 资格验证不通过；需看是否启用 API 补充及后续结果 |
| 订阅人数低于门槛 | `subscriber_count_below_minimum` | 筛选结果，通常无需技术故障重试 |
| 不要求资格校验／已通过 | `not_required`／`passed` | 正常业务结果 |
| API 返回没有该频道 | `status=failed, reason=channel_unavailable` | 补充信息不可用，不等同移除分类器已确认删除 |
| API 确认隐藏订阅人数 | `subscriber_count_hidden` | 来源限制；不能当成 0 |
| API 补充后人数仍不可用 | `subscriber_count_unavailable` | 与网络失败、低于门槛分别统计 |
| 发现页仍有待验证候选 | `settled=false` | 等待 Full Crawl 资格结果 |
| 页内存在验证失败候选 | `snapshot_validation_failed` | 当前分页策略停止继续；不要把技术失败算作低质量频道 |
| 没有候选／没有下一页／合格比例不足 | `no_candidates`／`no_continuation`／`qualified_ratio_below_threshold` | 正常分页终止原因，不是一组 HTTP 错误 |

查询词评分另有降级路径：[queryQuality.js](../services/qybullmq/src/queryQuality.js) 会产生 `scored_fallback`、`scored_partial`，原因可能是 `youtube_rate_limited`、`score_query_error`；解析契约错误在 `queryScoringErrorResult` 中继续抛出。当前限流判断使用独立文本正则，并未完全复用统一 YouTube 分类器。

### 3.3 空频道和地区复核

来源：[youtubeUploadsCountry.js](../services/qybullmq/src/youtubeUploadsCountry.js)、[videoActivityLifecycle.js](../services/qybullmq/src/videoActivityLifecycle.js)、[managedWorkerExecution.js](../services/qybullmq/src/managedWorkerExecution.js)。

| 标识 | 类型 | 当前含义与处理 |
| --- | --- | --- |
| `UPLOADS_COUNTRY_RECHECK` | code | 已知频道国家且符合复核条件时抛出；受管执行保存 requested 国家并返回 `country_recheck` 交接 |
| `UPLOADS_EMPTY_RESPONSE_UNVERIFIED` | code | 空解析结果没有足够原始证据，或原始视频 ID 与空解析矛盾；拒绝认定正常空列表 |
| `no_country` | 空列表判定 reason | 没有可用国家信息，空列表决策为 dormant |
| `country_checked` | 同上 | 当前出口地区已匹配频道地区 |
| `no_country_reserve` | 同上 | 该国家复核曾不可用 |
| `country_recheck_exhausted` | 同上 | 已经经过复核流程，不能无限交接 |
| `uploads_empty` | 生命周期原因 | 验证后的空 uploads 可导致休眠；不是 removed |

只有严格匹配的缺失播放列表证据才可作为已验证空 uploads；任意 `playlist not found` 文本不够。当前未处于受管执行而要求地区复核时抛普通 Error `Country recheck requires a managed execution`，没有单独 code。

## 四、YouTube 网络与解析分类

权威来源：[youtubeFailurePolicy.js](../services/qybullmq/src/youtubeFailurePolicy.js)，实际动作还取决于 [managedWorkerExecution.js](../services/qybullmq/src/managedWorkerExecution.js)、[worker.js](../services/qybullmq/src/worker.js)、[queues.js](../services/qybullmq/src/queues.js)。

| kind | 常见证据 | retry_mode | 其他当前决策 |
| --- | --- | --- | --- |
| `proxy_transport` | 可信代理／TLS／传输证据，407，SOCKS／隧道错误 | `new_identity` | `proxy_action=cooldown_network` |
| `upstream_transient` | 可信上游瞬态证据、5xx、部分 timeout/network 文本 | `same_identity` | 不自动判代理失效 |
| `youtube_rate_limited` | 429／限流文本 | `new_identity` | `cooldown_rate_limit` |
| `youtube_challenge` | 挑战文本或 `youtube_collection_failure=true` | `new_identity` | `cooldown_challenge` |
| `token_or_client` | 403、token／login／client unsupported 等 | `route_or_token` | `client_action=refresh_or_fallback` |
| `content_terminal` | 404、明确私密／删除／缺失内容等 | `none` | `terminal=true`，操作级终止 |
| `parser_contract` | name 为 `ParserContractError`／`IncrementalPlanContractError` | `none` | `terminal=true` |
| `parser_runtime` | 解析／JSON 错误、指定必需 surface 缺失 | `default` | 根错误为 `VIDEO_API_FALLBACK_UNRESOLVED` 时特殊改为 none、terminal |
| `database_contract` | 指定 SQLSTATE | `none` | `terminal=true` |
| `database_runtime` | 其他五位 SQLSTATE 形态／带数据库来源的错误 | `same_identity` | 只是粗分类，仍须判断 SQLSTATE 和提交状态 |
| `unknown` | 不匹配以上证据 | `default` | 不能解释为永久失败或无限可重试 |

分类器会检查 error、cause、AggregateError.errors，最多收集 20 个节点，并用优先级选择结果。常见优先次序为解析契约、数据库契约、带结构化证据的代理／上游失败、内容终止等；不是只看最外层字符串或第一个 HTTP 数字。

受管路由重试另会检查执行期累计 `failure_decisions`，其挑选规则不完全等于上表最终分类。当前 `applyFailureRetryDecision` 对 none 调 `job.discard()`，其余仅返回重试信息；实际网络授权、冷却和检查点交接由执行层完成，不能宣称这个函数单独实现了全部重试。

默认 BullMQ Job 配置为 3 次 attempts、5 秒基数指数退避、jitter 0.5，但具体 Job 可覆盖；Rota 路由尝试、API 等待与视频复查也不是同一个计数器。

### 4.1 指纹网关与超时证据

来源：[fingerprintGateway.js](../services/qybullmq/src/fingerprintGateway.js)。

| 原始 code | 当前含义 |
| --- | --- |
| `FINGERPRINT_PROXY_TRANSPORT` | 明确代理传输失败，保留 curlCode、source 等证据 |
| `FINGERPRINT_UPSTREAM_TRANSIENT` | 明确上游瞬态错误 |
| `FINGERPRINT_INVALID_TARGET_STATUS` | 目标响应状态异常；原始 target status 为 0 时分类器有特殊传输处理，其他情况可进入系统故障 |
| `FINGERPRINT_GATEWAY_ERROR` | 未细分的网关异常；结合 gatewayStatus、payload 与 message 处理 |

`gatewayStatus` 不等于 YouTube 的目标 HTTP 状态；`curlCode` 也不是 HTTP 状态。可信传输来源的 TimeoutError 可判代理传输，其他来源可能为上游瞬态。AbortError 可能是执行被取消，不能自动当网络波动。

### 4.2 解析与任务契约的准确名称

| 标识 | 是 code 还是 name | 当前事实／处理建议 |
| --- | --- | --- |
| `PARSER_CONTRACT_ERROR` | code；name 为 `ParserContractError` | 继承 BullMQ UnrecoverableError；保留 field、locale、source、reason、raw_value、context；修复解析后受控重放 |
| `IncrementalPlanContractError` | name，无独立 code | 缺失／非法计划字段；当前通用分类为 parser_contract；修复生产者与契约 |
| `FULL_CRAWL_FETCH_CONTRACT_CONFLICT` | code；name 为 `FullCrawlFetchContractError` | 执行器／版本／哈希契约冲突；不在通用分类器的上述 name 专门分支中，不能假定一定自动停止重试 |
| `YoutubeJsRequiredSurfaceError` | name | 指定必需 surface 缺失；匹配条件下分类为 parser_runtime |
| `VIDEO_API_FALLBACK_UNRESOLVED` | code | API 兜底后仍未解决必需内容；通用选择器对根错误设不可重试 |

依据：[localizedParsing.js](../services/qybullmq/src/localizedParsing.js)、[incrementalPlan.js](../services/qybullmq/src/incrementalPlan.js)、[fullCrawlFetchContract.js](../services/qybullmq/src/fullCrawlFetchContract.js)、[videoApiBatchRequests.js](../services/qybullmq/src/videoApiBatchRequests.js)。Full Crawl 存在多个 fetch contract，评论要求与 API 兜底策略不同，不能只按一个最新版本解释全部任务。

## 五、频道内视频的失败与正常排除

来源：[youtubePlayability.js](../services/qybullmq/src/youtubePlayability.js)、[detailPolicy.js](../services/qybullmq/src/detailPolicy.js)、[videoDisposition.js](../services/qybullmq/src/videoDisposition.js)。以下为 playability 的 `reason_code`，不全是 error.code。

| reason_code | 当前分类 | 处理边界 |
| --- | --- | --- |
| `bot_challenge` | collection_failure，unknown access | 可转 `YoutubeCollectionFailureError`；不写成不可用视频事实 |
| `members_only` | content，members_only | 访问属性，不等于频道失败 |
| `private` | content，private | 视频级访问状态与低频复查 |
| `age_restricted` | content，public access＋age_restricted availability | 保留限制证据；不能仅看 public 丢掉年龄限制信息 |
| `region_restricted` | content，public access＋region_restricted，建议 alternate_region | 该分类返回值不保证所有调用方已执行地区切换 |
| `uploader_removed`、`copyright_removed`、`account_terminated`、`not_found`、`removed` | content，unavailable | 这里是播放器内容判断，不直接触发频道移除 |
| `playable` | content，public | 正常结果 |
| `unsupported_login_required_reason` | inconclusive，alternate_client | 泛 LOGIN_REQUIRED 尚不能判私密 |
| `generic_video_unavailable`、`unsupported_playability_reason`、`playability_unresolved` | inconclusive，alternate_client | 需要补充证据，不直接判永久无内容 |

视频处置还保留重查时间；`retryable=false` 可以表示不立即重试，不表示永远不检查。

| 处置原因 | 当前 resolveVideoDisposition 典型返回 | 复查间隔 |
| --- | --- | --- |
| `upcoming_live`／`live_in_progress` 作为 terminalReason | terminal_excluded | 24 小时 |
| `outside_content_window` | terminal_excluded | 30 天 |
| `access_private`／`access_unavailable` | terminal_excluded | 7 天 |
| `discovery_scan_incomplete` | deferred | 1 小时 |
| `detail_collection_failed` | deferred | 1 小时 |
| `authoritative_type_unresolved` | deferred | 6 小时 |
| 其他未决 access | deferred，`access_<status>` | 6 小时 |
| `content_stored`／`content_access_updated` | stored | 不安排该处置的立即补抓 |

以上受分支顺序、priorDisposition、storageAction 等影响：已有内容可能仅更新访问状态，已有 terminal_excluded 可被保留。详情层还可能返回 partial 或走 emergency API；不要用一个视频异常直接重启整个频道。

## 六、API、配额和 Agent

### 6.1 Data API 与等待控制流

来源：[youtube.js](../services/qybullmq/src/youtube.js)、[pipelineV2.js](../services/qybullmq/src/pipelineV2.js)、[videoApiContinuation.js](../services/qybullmq/src/videoApiContinuation.js)、[channelApiFallback.js](../services/qybullmq/src/channelApiFallback.js)。

| 情况 | 当前标识／处理 | 建议 |
| --- | --- | --- |
| 等待持久 API 结果 | `VIDEO_API_PENDING`，记录 requestId、waiting_downstream／DelayedError | 沿原 requestId 等待，遵守数据库 next_retry_at |
| API 回放仍需网络步骤 | `VIDEO_API_NETWORK_REQUIRED` | 重新进入受管网络执行；不能在离线回放中绕过授权 |
| 视频批量本地每日额度不足 | 返回 `ok=true, deferred=true, reason=daily_request_limit_reached` | 延期至数据库日界后的次日 5 分钟；与上游官方配额错误分开 |
| 频道 API 补充本地额度不足 | 普通 Error：`channel data api daily request limit reached` | 当前不走同一结构化延期协议；重构应统一 |
| 缺 API Key | 普通 Error：`youtube data api key missing` 或频道 fallback 对应文本 | 配置故障；告警并暂停受影响路径，不重复全量抓取 |
| videos.list／channels.list HTTP 失败 | 普通 Error，message 含 status 和 API message | 目前没有统一保留 api reasons；不能声称已完整区分官方配额／权限／参数错误 |
| commentThreads 的 `commentsDisabled` | 返回 status=disabled，写评论禁用证据 | 正常内容状态，不是频道失败 |
| 其他 commentThreads HTTP 失败 | code 为首个上游 reason，缺失时 `HTTP_<status>`；另有 api_reasons | 保留上游原码，不能把全部 403 都判客户端 token 问题 |

当前 API Key 尝试与本地每日请求预约是现有代码行为，不等于官方项目配额的完整模型。重构应按来源保存状态、官方 reason、重试时间及配置版本；增加可识别的配额／认证／参数分类，而不是靠报错文本猜测。

### 6.2 Agent 后处理

### 8.1 传输错误与结果回执

来源：[protocol.js](../services/qybullmq/src/remoteNodes/protocol.js)、[natsProtocol.js](../services/qybullmq/src/remoteNodes/natsProtocol.js)、[natsClient.js](../services/qybullmq/src/remoteNodes/natsClient.js)、[channelPlanExecutor.js](../services/qybullmq/src/remoteNodes/channelPlanExecutor.js)、[wholeChannelNode.js](../services/qybullmq/src/remoteNodes/wholeChannelNode.js)。

| code／文本 | 常见协议状态 | 当前语义／建议 |
| --- | --- | --- |
| `NATS_TRANSPORT_UNAVAILABLE` | 503 | RPC 传输不可用；恢复连接，核验有副作用操作是否已完成 |
| `NATS_RESULT_PENDING` | 503 | 发布／查询结果尚无持久回执；不能认定采集失败 |

| `BATCH_CONFLICT` | 默认 409 | 同批身份冲突；需要核验内容，执行器停止循环 |
| `UNAUTHORIZED` | 401 | 节点不存在／禁用／认证不通过等；修复授权 |

| `INVALID_JSON`、`INVALID_COMPRESSED_RESULT`、`INVALID_RESULT` | 400 | 序列化／契约错误；隔离问题输入 |
| `INVALID_ID`、`NON_CANONICAL_ID`、`INVALID_GENERATION`、`INVALID_WORKER_SLOT` | 400 | 请求身份格式错误 |
| `SPOOL_FULL` | 无统一状态；是普通 Error.message | 节点 spool 容量不足；降低准入、恢复交付，禁止删除未确认数据腾空间 |

`RemoteProtocolError` 默认 status=409，所以不能把所有 409 都看成同一种永久冲突。普通命令上传失败为 400/401/403/404/409/413/415 时，当前路径会 block pending 文件；确认的 STALE_LEASE 单独转 .stale。整频道上传只有专门 stale 归档分支，并不完全复用相同 block 逻辑。

执行器外层会因 400/401/403/404/413/415 或 BATCH_CONFLICT 停止，其余错误可能进入退避循环。文档建议把长期重复的契约冲突提升为隔离／告警，但不能说当前已统一做到。

远程业务错误通过 [channelWire.js](../services/qybullmq/src/remoteNodes/channelWire.js) 保留 name、code、cause、AggregateError 等白名单字段；这与 NATS RPC failure 包装是不同层。DOMException 的数字 code 会在结果协议中规范化，并保留 native_code，20／23 不是 HTTP 错误码。

### 9.1 SQLSTATE

下表前七项是当前 YouTube 分类器明确列入 database_contract 的码；后续项是排障应保留的数据库原生码与建议，不代表各 Store 已统一实现这些重试。

| SQLSTATE | 含义 | 当前／建议处理 |
| --- | --- | --- |
| `22001` | 字符串超长 | 当前通用策略不重试；查字段和输入约束 |
| `22P02` | 文本表示无法转换 | 同上；查类型转换与序列化 |
| `23502` | NOT NULL 违反 | 同上；不能随手补默认值掩盖缺失事实 |
| `23503` | 外键违反 | 同上；查引用归属和事务顺序 |
| `23505` | 唯一约束违反 | 先看 constraint：同键同内容可能是正常幂等，同键不同内容是冲突 |
| `23514` | CHECK 违反 | 当前通用策略不重试；查业务状态组合 |
| `42804` | 数据类型不匹配 | 当前通用策略不重试；修复 SQL／契约 |
| `40001` | 序列化失败 | 建议有界重做完整事务，重新读并校验前置条件 |
| `40P01` | 死锁 | 建议完整事务退避重试并治理锁顺序 |
| `55P03` | 无法取得锁 | 检查 NOWAIT／锁超时与竞争；按业务时限退避 |
| `57014` | 查询被取消，包括 statement timeout | 先区分主动取消与超时；不能默认为网络失败 |
| `25P02` | 当前事务已失败 | 先回滚；后续语句错误可能只是前一个错误的结果 |
| `53300`／连接类 `08xxx` | 连接耗尽／连接异常 | 降并发、排查池与连接；COMMIT 阶段断线先查幂等回执 |

两个当前明确例外：远程 `store.js` 对特定 `remote_channel_scope_lease` 的 23505 可返回无任务，避免把竞争当故障；`videoActivityLifecycle.js` 的证据查询会回滚到保存点，将 57014 返回为 timedOut。这证明不能仅凭 SQLSTATE 绕过调用方逻辑。

## 十、增量最终失败记录的口径

[incrementalTerminalFailure.js](../services/qybullmq/src/incrementalTerminalFailure.js) 还有独立的失败归类：`channel_removed`、`channel_unavailable`、`timeout`、`proxy_failure`、`parser_failure`、`crawler_failure`。

最终观察的 `outcomeReasonCode` 为 `<domain>_<failure_kind>`，domain 为 about／video／agent，例如 `video_timeout`。这些是最终观察口径，与 `youtube_failure_decision.kind` 不同。通常在明确永久失败、频道终止或 attempts 耗尽后记录；已有重试机会时可返回 `retry_pending`。

该函数明确跳过 `CONTENT_DETAIL_EXECUTION_FENCE_STALE` 和恢复等待，避免替新执行写终局失败。它选择尚未处于 complete／partial／queued 的待处理域，幂等键含运行与尝试次数；重放同一次失败复用已提交 observed_at。不要根据“视频失败”文本自行补写整个运行的三个域失败。

## 十二、目标错误契约与 Temporal 映射（尚未实现）

建议定义如下结构；字段为设计名，不能当作现有日志格式直接写生产告警：

```text
error_version / mapping_version
phase / source / entity_scope
raw_code / raw_name / http_status / sqlstate / provider_reason
category / action / retry_at / retry_budget_kind
channel_id / run_id / logical_batch_key / execution_epoch
received_receipt_id / applied_receipt_id
evidence_ref / cause_summary / first_seen_at
```

建议 action 只表达清楚的有限动作：完成并记录内容状态、延期等待、重试当前事务／步骤、重新取得合法执行权、停止旧执行、停止当前运行、隔离并人工修复。错误码与动作分开版本化；一个 code 在不同提交阶段可能需要不同动作。

Temporal 迁移原则：

1. 网络失败在 Activity 边界有界重试；对象读取／解析在事务外，数据库提交按稳定业务键幂等。
2. `VIDEO_API_PENDING`、资源延期、已知配额重置应返回结构化等待结果，Workflow 用 Timer／持久条件继续，避免 Activity 长期占位睡眠。
3. 频道明确删除、视频排除、订阅人数不达标作为带证据的业务结论处理，不用整条 Workflow 的技术失败代替。
4. 解析／任务契约冲突映射明确的不可重试 ApplicationFailure 类型，修复后走受控重放；不要把每个 SQL 唯一冲突都设成不可重试。
5. 旧 execution_epoch 已失权时终止旧副作用；Temporal timeout／cancel 不能代替数据库栅栏或 Rota 网络授权失效。
6. SQL 40001／40P01 在确认回滚后重做完整短事务；提交不确定则以同一批次回执恢复，避免多层重试放大。
7. 基础设施、路由、业务运行、API 配额和人工重放预算分别计量；不得靠每次新建 Workflow ID 重置全部预算。

## 十三、应补的验收场景

这些是后续开发验收要求，本次没有执行测试。

| 输入／故障 | 必须验证的结果 |
| --- | --- |
| 视频 404，频道仍正常 | 只更新视频结论，不移除频道 |
| 明确频道终止 alert | 保存具体 removed_reason 和证据；重复处理幂等 |
| 自发现人数缺失，快照后补全 | 先 needs_snapshot，再按资格结果结算 |
| 解析得到空列表但原始含视频 ID | 抛未验证空响应，检查点和休眠状态不错误推进 |
| 相同 timeout 来自网站、数据库、主动取消 | 保留来源并执行不同动作 |
| 相同 HTTP 403 来自页面、Data API、Agent | 分别判断内容／客户端、配额权限、模型认证 |
| API pending 跨日额度延期 | 保留 requestId 与 next_retry_at，不重复全频道抓取 |
| 同键同内容重复提交／同键不同内容 | 前者返回原回执，后者隔离 |
| 事务提交后断线、对象回执丢失 | 幂等恢复，不重复观察／发布序列 |
| 旧节点在新执行后提交 | 拒绝旧写入，不替新执行记录失败 |
| RPC 包装、业务 wire、AggregateError 往返 | 必需 name/code/source/cause 不丢，分类优先级可解释 |
| spool 满、journal 缺失、STALE_LEASE | 未确认结果受保护；终止／归档／恢复按分路径契约执行 |

团队讨论建议先锁定三件事：哪些证据允许改变频道生命周期；哪些错误允许自动重试且使用哪个预算；哪些步骤已有持久回执、只能续跑而不能重新采集。其余分类和告警围绕这三项展开。
