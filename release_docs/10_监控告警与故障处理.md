# 10 监控指标、告警与故障处理手册

状态：当前观测入口与待补监控方案。本轮没有部署新的采集器、告警或修改配置。基线见 [01](01_目标范围与系统基线.md)。负责人角色：运维、值班开发、数据库。

## 值班首先看什么

先确认数据正确性和磁盘安全，再看端到端完成量与最老积压，最后按时延分解定位 CPU、网络或 SQL。不能只看“45 个 Worker 在线”或“容器健康”。

当前根文件系统约 93% 占用、剩余约 40G 是需要及时复核的容量信号。它不自动证明数据库正在报错，但要求明确净增长和应急空间，不能继续无预算地在同盘添加重负载。

## 指标分组

| 层次 | 必需指标 | 当前可用来源/缺口 |
| --- | --- | --- |
| 业务 | 首次全量与增量完成数、失败分类、发布延迟 | Run/Plan/观测/发布状态；统一口径待完善 |
| 采集节点 | connected/requested/accepting/active、重启、spool、采集耗时 | 节点状态、日志和本地暂存；阶段耗时覆盖需核查 |
| 中心 | 结果接收/应用耗时、在途工作、CPU throttling、event-loop、RSS | 容器与日志；完整分阶段指标待开发 |
| NATS | pending、unacknowledged、RPC/心跳准入、流容量 | 中心 `remote_nats_status`；字节与现场流配置另核对 |
| PostgreSQL | 连接等待、锁、长事务、I/O、临时文件、WAL、自动清理 | 系统视图/宿主机指标；采集库本次未安装 `pg_stat_statements` |
| Redis/BullMQ | waiting/active/delayed/failed、队列年龄、内存、持久化状态 | 队列 API、Redis 指标；delayed 不应全部当作可运行积压 |
| Rota/代理 | 就绪路由、租约冲突、预算耗尽、网络/国家重检失败 | Rota 及 Worker 日志 |
| 后处理 | Agent/Finalize/Projection 积压、最老年龄、重试 | 对应队列与发布表 |
| 存储 | 文件系统余量、数据库/对象/日志增长、备份年龄 | 文件系统、系统目录、备份系统 |
| OLAP〔将来〕 | 同步延迟、重复/迟到、校验差异、源 WAL 积压 | 新同步链路必须交付 |

指标标签使用角色、节点、结果类别和有限错误码。完整 channel_id、URL 或任意错误字符串不应作为高基数时序标签；详细关联 ID 放受控日志与追踪。

## 告警原则

- 正确性告警：旧代次写入被接受、重复业务事实、发布版本倒退，立即升级。
- 容量告警：按剩余可用天数、恢复余量和增长率设置，同时保留使用率阈值；93% 是本次实际占用，不是已批准的统一报警阈值。
- 吞吐告警：有到期可执行任务却持续低完成量；排除原策略休眠、未来 eligible 与 API 等待。
- 积压告警：最老年龄及增长斜率持续恶化；单个瞬时 pending>0 不必视为故障。
- 可用性告警：中心反复重启、多个节点失联、数据库连接耗尽、NATS 无法持久接收。

具体连续时长和数值由第 06/12 份基线与服务目标确定，避免把未验证的建议当作生产阈值。告警要带责任人、影响角色、首查入口与回退动作。

## 只读检查示例

以下命令不展示凭据，但日志内容仍需脱敏；SQL 在目标数据库的受控只读会话执行。命令均供后续排查，本轮文档编写不执行它们。

```bash
date -u
df -h
free -m
docker ps --format '{{.Names}}\t{{.Image}}\t{{.Status}}'
```

容器统计只选择目标服务，避免为排查不断高频采样所有实例：

```bash
docker stats --no-stream qy-remote-node-center qy-remote-nats
```

低开销数据库概览示例：

```sql
BEGIN READ ONLY;
SET LOCAL statement_timeout = '5s';
SET LOCAL lock_timeout = '1s';
SELECT current_database(), pg_database_size(current_database());
SELECT state, wait_event_type, wait_event, count(*)
FROM pg_stat_activity
WHERE datname = current_database()
GROUP BY state, wait_event_type, wait_event;
SELECT schemaname, relname, n_live_tup, n_dead_tup,
       pg_total_relation_size(relid) AS total_bytes,
       last_autovacuum, last_autoanalyze
FROM pg_stat_user_tables
ORDER BY pg_total_relation_size(relid) DESC
LIMIT 12;
COMMIT;
```

这些是估计和快照，不是精确业务计数。全量 SQL 文本可能含敏感参数，收集锁/慢 SQL 时应脱敏。`EXPLAIN ANALYZE` 不属于纯计划读取。

## 故障处理矩阵

| 症状 | 首先区分 | 可评审的缓解动作 | 禁止误操作 |
| --- | --- | --- | --- |
| Worker 在线但完成慢 | 采集慢、未分配、回传慢、应用慢、收尾慢 | 暂缓增加接单，按耗时与资源定位 | 仅凭在线数扩大 Worker |
| NATS pending 持续增长 | 消费者停滞、DB 慢、流容量、消息错误 | 恢复消费者/减新接单，保留已有结果 | 清空结果流 |
| 中心反复重启 | 异常退出、OOM、资源限额、恢复循环 | 保存错误证据，按角色回滚/修复 | 不看 spool 直接重建全部节点 |
| 数据库连接耗尽 | 连接泄漏、专用会话、并发池总量 | 降低低优先级新工作，审查池预算 | 直接把所有直连改事务池 |
| 锁超时/租约冲突 | 节点级锁、长事务、旧任务未收尾 | 按原恢复路径排空/续收尾 | 删除锁/更新代次绕过约束 |
| 节点 spool 满/损坏 | 未确认、过期证据、格式错误 | 停该节点新接单，保存文件与身份后修复 | 手工删 pending 文件当修复 |
| API waiting 增长 | 配额、未完成批次、continuation 故障 | 修复共享 API/续跑，保持预算 | 所有 Worker 各自重试 API |
| 发布停滞 | Inbox/Revision/Projection/业务 SQL | 按阶段恢复与重放 | 手工标 delivered 掩盖差异 |
| 统计页面失败 | 统计连接/共享内存/慢扫描 | 缓存、降级展示、限制查询并发 | 让统计失败阻断列表和任务控制 |
| 磁盘不足 | PG 数据/WAL、对象、日志、镜像、其他卷 | 扩容或经核对清理可删除对象 | 删除 WAL、生产卷、任意测试容器 |

## 特别注意的历史问题

历史记录曾出现每 Worker 长驻锁/LISTEN 连接、周期健康检查反复导入采集依赖、共享节点行锁竞争、错误载荷导致重启循环，以及统计并行扫描耗尽共享内存。

这些记录用于建立排查清单，不作为当前根因。当前源码已有连接共享、轻量节点健康管理、统计隔离等修改，必须核对受影响容器版本是否包含修复。

数据库 Docker `HostConfig.ShmSize` 可能仍为旧 64 MiB，而历史记录包含在线 remount 至 200 MiB；重启旧容器可能恢复旧元数据限制。先检查容器实际 `/dev/shm` 挂载和有效 Compose，再处理，不能仅凭一个字段判断实际容量。

## 故障记录与关闭

事件记录至少包括 UTC 时间范围、受影响角色和镜像、Plan/Run 示例、原始症状、只读证据、临时缓解、根因是否已证明、实施变更、验证范围、剩余风险和恢复接单数。

关闭条件：原失败路径验证恢复、数据差异核对、积压恢复可控、无重复业务副作用、临时调试撤除、文档与告警更新。进程重启后短时恢复不等于根因已解决。
